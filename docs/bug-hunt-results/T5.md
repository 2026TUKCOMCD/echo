# T5. 부팅/업데이트 후 복구 — 버그 감사 결과

## 발견 목록

### [심각도: 상] BootReceiver가 시스템 브로드캐스트를 수신하지 못함
- **파일**: `android/app/src/main/AndroidManifest.xml:92`
- **증상**: 기기 부팅 후 또는 앱 업데이트 후 BootReceiver가 BOOT_COMPLETED 및 MY_PACKAGE_REPLACED 브로드캐스트를 수신하지 못합니다. 
  - 시나리오: 사용자가 대화 알람(예: 매일 오후 3시)과 위치 수집 알람(예: 아침 6시~오후 9시)을 설정한 후 기기를 재부팅하거나 앱을 업데이트하면, 저장된 알람 설정이 복원되지 않으므로 알람이 작동하지 않습니다. 사용자는 앱을 다시 켜서 알람을 재설정해야 합니다.
- **근거**: 
  ```xml
  <!-- AndroidManifest.xml 줄 90-97 -->
  <receiver
      android:name=".data.receiver.BootReceiver"
      android:exported="false">  <!-- ← 버그: exported="false" -->
      <intent-filter>
          <action android:name="android.intent.action.BOOT_COMPLETED" />
          <action android:name="android.intent.action.MY_PACKAGE_REPLACED" />
      </intent-filter>
  </receiver>
  ```
  
  Android 12 이상에서 intent-filter를 가진 BroadcastReceiver는 반드시 `android:exported="true"`로 명시해야 시스템(또는 다른 앱)이 해당 receiver를 찾고 브로드캐스트를 보낼 수 있습니다. `exported="false"`로 설정하면 시스템이 이 receiver를 무시하고 BOOT_COMPLETED, MY_PACKAGE_REPLACED 브로드캐스트를 보내지 않습니다.
  
  따라서:
  1. BootReceiver.onReceive() (BootReceiver.kt:21-32)가 호출되지 않음
  2. handleRestart(context) (BootReceiver.kt:37-43)가 실행되지 않음
  3. ConversationAlarmScheduler.rescheduleFromStorage() (ConversationAlarmScheduler.kt:114-130)이 실행되지 않음
  4. LocationScheduler의 복구 로직 (LocationScheduler.kt:45-61)이 실행되지 않음
  5. 모든 알람이 복원되지 않으므로 기능이 완전히 작동하지 않음

## 체크리스트 판정

### ☑ 체크 1: BootReceiver가 위치 수집 알람과 대화 알람을 둘 다 복원하는가
**판정**: 문제 없음 (코드 수준)

BootReceiver.handleRestart() (줄 37-43)에서:
- 줄 39: `scheduleLocationCollection(context)` → 위치 수집 복원
- 줄 42: `ConversationAlarmScheduler.rescheduleFromStorage(context)` → 대화 알람 복원

두 가지 모두 복원 로직이 구현되어 있습니다. 단, **발견 #1의 exported="false" 버그로 인해 onReceive()가 호출되지 않으므로 실제로는 복원되지 않습니다.**

### ☑ 체크 2: MY_PACKAGE_REPLACED 처리 시 업데이트 후 복원 로직이 안전한가
**판정**: 문제 없음

BootReceiver.onReceive() (줄 22-31)에서 BOOT_COMPLETED(줄 23)와 MY_PACKAGE_REPLACED(줄 27) 모두를 처리합니다.

저장 형식 호환성:
- ConversationAlarmStorage: SharedPreferences에 "HH:mm" 문자열로 저장 (줄 20-28)
- LocationCollectionStorage: SharedPreferences에 "HH:mm" 문자열로 저장 (줄 22-24)

저장 형식이 간단하고 버전 마이그레이션이 필요 없으므로 안전합니다. 단, **발견 #1로 인해 onReceive()가 호출되지 않으므로 실제로는 복원이 시도되지 않습니다.**

### ☑ 체크 4: 알람 복원 시 과거 시각이 저장돼 있으면 즉시 발화/과거 시각 스케줄이 되는가
**판정**: 문제 없음

val calendar = Calendar.getInstance().apply {
    timeInMillis = System.currentTimeMillis()

### ☑ 체크 5: Manifest에 RECEIVE_BOOT_COMPLETED 권한과 intent-filter, exported 설정이 적절한가
**판정**: **발견 #1 — exported="false" 설정 오류**

상세 검토:
- **줄 22**: `<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />` ✓ 권한 있음
- **줄 93-96**: 
  ```xml
  <intent-filter>
      <action android:name="android.intent.action.BOOT_COMPLETED" />
      <action android:name="android.intent.action.MY_PACKAGE_REPLACED" />
  </intent-filter>
  ```
  ✓ 두 액션 모두 포함

- **줄 92**: `android:exported="false"` ✗ **오류**
  - Android 12+ 정책: intent-filter가 있으면 exported를 명시해야 함 (줄 92에서 함)
  - 하지만 값이 "false"로 설정되어 있음
  - BOOT_COMPLETED, MY_PACKAGE_REPLACED는 시스템이 보내는 브로드캐스트이므로 `exported="true"`여야 시스템이 receiver를 찾을 수 있음
  - 현재 설정으로는 시스템이 이 receiver를 무시하고 브로드캐스트를 보내지 않음

**수정 방안**: `android:exported="true"`로 변경

### 발견 #1 — 기각 (오탐, 근거의 사실 오류)

`android:exported="false"`인 receiver도 **시스템이 보내는 브로드캐스트는 수신한다.**
Android 공식 문서의 `android:exported` 정의: "false인 경우, 해당 receiver가 받을
수 있는 메시지는 **시스템**, 같은 애플리케이션의 컴포넌트, 또는 같은 user ID를
가진 앱이 보낸 것뿐이다." BOOT_COMPLETED와 MY_PACKAGE_REPLACED는 시스템만 보낼
수 있는 protected broadcast이므로 exported="false"여도 정상 수신된다.

Android 12+의 요구사항은 intent-filter가 있는 컴포넌트에 exported 값을
**명시**하라는 것이지 "true"로 하라는 것이 아니며, 현재 Manifest는 이를 충족한다
(AndroidManifest.xml:92). 오히려 시스템 브로드캐스트만 받는 receiver에
exported="false"를 쓰는 것이 공격 표면을 줄이는 **보안 모범 사례**다. 즉 현재
설정이 올바르며, haiku가 제시한 수정 방안("true"로 변경)을 적용해서는 안 된다.

### 나머지 체크리스트 판정 — 확인

- 체크 3 (동기 처리): BootReceiver 호출 경로가 모두 동기임을 확인. 판정 유지.
- 체크 4 (과거 시각): ConversationAlarmScheduler와 LocationScheduler 모두
  `timeInMillis <= System.currentTimeMillis()`이면 다음날로 미루는 로직을 확인.
  판정 유지.
- 보충 확인: 두 스케줄러 모두 API 31+에서 `canScheduleExactAlarms()` 가드 후
  setExactAndAllowWhileIdle을 호출하고, 권한 없으면 일반 알람으로 폴백한다 —
  부팅 직후 SecurityException 크래시 경로 없음.
