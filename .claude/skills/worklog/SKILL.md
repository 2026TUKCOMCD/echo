# 오늘 작업 기록 (노션 + Slack)

## 사전 준비 (팀원 각자)
- Claude Code에 **Notion MCP**와 **Slack MCP**가 연결되어 있어야 한다. 없으면 해당 단계는 진행하지 말고 연결이 필요하다고 알린다.
- `gh auth login`으로 GitHub CLI 로그인이 되어 있어야 한다 (PR 조회용).

## 인자
- 없음: 노션 작성 → Slack 전송
- `notion`: 노션만
- `slack`: Slack만 (오늘 노션 페이지가 이미 있으면 링크만 붙임)

## 고정 설정
- 노션 위치: 레포에는 고정값 없음. 개인 기본값은 아래 「개인 설정」 파일로 두고, 매번 사용자에게 확인한 뒤 Notion 검색으로 찾는다 (아래 2-1).
- 노션 제목: 오늘 날짜 `YY/MM/DD` (예: 26/09/24)
- Slack 채널: `C0C3ZJV1RL5` (이 채널 외에는 절대 보내지 않는다)
- 날짜 기준: Asia/Seoul 오늘 00:00 이후
- 작성자 이름: `git config user.name`

## 개인 설정 (선택, 커밋되지 않음)
- 위치: 레포 루트(`git rev-parse --show-toplevel`)의 `.claude/worklog.local.md` (`.gitignore`로 제외됨)
- 형식:
  ```
  notion_default_page: <노션 페이지 이름>
  ```
- 파일이 없거나 값이 비어 있으면 기본값 없이 묻는다. 이 파일은 읽기만 하고 스킬이 만들거나 고치지 않는다.

## 1. 재료 모으기 (세 곳 모두)
1. **GitHub (뼈대, 가장 신뢰)**
   - 오늘 내 커밋: `git log --all --since="<오늘> 00:00" --author="<이름>" --no-merges --oneline`
   - 오늘 내 PR: `gh pr list --author @me --state all --search "updated:>=<오늘>"` (번호·제목·상태·대상 브랜치)
2. **노션**: 2-1에서 기록 위치를 먼저 확정한 뒤, 그 아래에 오늘 날짜 페이지가 있는지 확인하고 있으면 읽는다.
   - `slack` 인자면 위치를 묻지 않고, 오늘 날짜 제목으로 Notion 검색해 내 페이지가 있으면 링크 후보로 보여 준다.
3. **현재 세션 대화 (보충)**: 1·2에 없는 일(조사, 실측, 결정, 문서 정리)만 보충한다.
- 출처끼리 다르면 GitHub을 따르고 미리보기에 "⚠️ 확인 필요"로 표시한다.
- 오늘 한 일이 없으면 아무것도 쓰거나 보내지 않고 그렇다고만 알린다.

## 2. 노션 정리 (`slack` 인자면 건너뜀)
1. **위치 확인**: 「개인 설정」의 `notion_default_page`가 있으면 "「<기본값>」 아래에 쓸까요? 다른 곳이면 페이지 이름을 알려 주세요"라고,
   없으면 "노션 어느 페이지 아래에 쓸까요? 페이지 이름을 알려 주세요"라고 묻는다.
   - 확정된 이름을 Notion 검색으로 찾는다. 기본값으로 찾지 못하면 설정 파일 값을 고치라고 안내하고 다시 묻는다. 결과가 1개면 제목·상위 페이지를 보여 주고 확인받는다.
   - 여러 개면 제목·상위 페이지 목록을 보여 주고 고르게 한다. 없으면 다시 묻는다 (상위 페이지를 새로 만들지 않는다).
   - 찾은 페이지 ID는 이번 실행에서만 쓰고 파일에 기록하지 않는다.
   - 팀 메인 페이지(「종합설계, 컴응설 11조 , S5」) **바로 아래에는 새 페이지를 만들지 않는다** (메인은 시간순 배치가 중요).
2. 그 위치에 오늘 날짜 페이지가 **이미 있으면 새로 만들지 않는다.** 먼저 묻는다:
   "기존 페이지 끝에 오늘 추가분을 덧붙일까요, 건너뛸까요?"
3. 문체는 팀원이 읽는 **중립적인 문서체** (말투 규칙 적용 안 함). 형식:
   - 맨 위 요약 콜아웃 (📌, 2–3문장)
   - 작업별 `##` 섹션: 배경 → 한 일/결정 → 결과(숫자는 표) → PR 링크
   - 마지막: 남은 일 체크리스트 (`- [ ]`)
4. **미리보기**: 노션에 쓸 내용을 그대로 보여 준다 → 사용자가 명시적으로 승인하면 작성한다.
5. 작성 후 페이지 링크를 확보한다 (Slack 메시지에 사용).
- 기존 페이지나 상위 페이지의 다른 내용·순서는 절대 건드리지 않는다 (추가만).

## 3. Slack 전송 (`notion` 인자면 건너뜀)
1. 메시지 형식 (짧은 요약형):
```
📌 <이름> 작업 요약 · M/D(요일)

• <작업 1> → <결과> (PR #번호 상태)
• <작업 2> → <결과> (PR #번호 상태)
• <작업 3> → <결과> (PR #번호 상태)

⚠️ 팀원 확인 필요: <팀원이 해야 할 일, 한 줄. 없으면 이 줄 생략>
📄 자세히: <오늘 노션 페이지 링크. 없으면 생략>
```
   - 작업 줄은 **정확히 3줄**로 쓴다. 작업이 더 많으면 합치고, 적으면 남은 일이나 다음 할 일로 채운다. 중요한 순서로 쓴다.
   - 한 줄은 **약 40자 안쪽**으로 쓴다. 형식은 `무엇 → 결과 (PR #번호 상태)`이고, 이유·세부 숫자·설명은 노션으로 미룬다.
   - 예: `• 시작 음성 스트리밍 → 9.7초에서 약 3초로 (#451·#452 머지)`
2. **미리보기**: 메시지를 그대로 보여 준다 → 사용자가 "보내" 등으로 명시적으로 승인한 경우에만
   Slack MCP의 메시지 전송 도구로 `C0C3ZJV1RL5`에 보낸다. 수정 요청이 오면 고쳐서 다시 미리보기.
3. 전송 후 결과(메시지 링크)를 알려 준다. 실패하면 오류를 그대로 보고하고, 재시도는 묻는다.

## 공통 규칙
- **민감정보 금지** (노션·Slack 모두): API 키·토큰, 서버 IP/주소, SSH 정보, 사용자 ID·개인정보, 대화 원문
- 승인 없이 쓰거나 보내지 않는다. 한 단계가 실패해도 다른 단계를 몰래 진행하지 않는다.
